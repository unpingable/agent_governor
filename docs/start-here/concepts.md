# Concepts — plain words first

> STATUS: CANDIDATE (docs-professionalization D-2)

This project's deeper documentation uses a precise internal vocabulary.
You do not need it to start. The bridge:

| Plain term (used here) | Precise term (used in deep docs) |
|---|---|
| component | organ |
| system / component set | constellation |
| what can be relied on | admissibility |
| proposed / not yet accepted | candidate |
| public claim / accepted claim | minting |
| observed evidence | witness testimony |
| permission / scoped authority | standing |
| blocked because required evidence/action is missing | obstruction |
| what agents are not allowed to do | non-grant |

The precise terms exist because the plain ones blur exactly where it
matters — "valid" versus "still usable," "logged" versus "sealed." Once
you've seen the demo, the [glossary](https://unpingable.com/glossary.html)
carries the full set.

## The sharp parts (deliberately kept sharp)

These are the product. Cleaning up the docs never softens them:

- **Refusal is normal.** A gate that cannot say no, with a reason on the
  record, is decoration.
- **Agents do not self-approve.** A written "approved" is prose until the
  approving act is independently witnessed.
- **Evidence can be stale.** Valid-when-checked is not valid-when-used;
  the gap between the two is measured, on a named clock.
- **Schema-valid is not admission.** A well-formed artifact proves shape,
  never permission.
- **Memory is not authority.** Stored state is findable; reliance on it
  must be separately earned.
- **Schedule is not consent.** Work deferred to later is held until its
  conditions can be checked — deferred does not mean trusted later.
- **Green tests are not total truth.** A passing suite is evidence with a
  scope, and the exit code is read directly, never through a pipe that can
  mask it.
