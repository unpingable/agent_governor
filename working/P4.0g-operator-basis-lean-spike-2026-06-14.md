## What the receipt is (goblin translation, operator 2026-06-14)
Not "James blessed it." It is: *a qualified operator reviewed this specific basis
bundle before the transition, and the system can prove it was the same bundle later
consumed.* It establishes **review-happened**, never **promotion-eligible**.

## The negative shape (what the receipt must NOT do), each with a warrant

1. **Pre-state binding — witness valid in S, not S′.** The basis reviewed must be the
   pre-transition basis; the promotion must consume the *same* bundle.
   → `basis_bundle_hash` + `prior_authority_hash` bind the pre-state; the gate refuses
   if the consumed bundle ≠ the reviewed bundle.
   Warrant: `AmendmentFragment` type discipline [annex].

2. **Post-attestation ≠ authorization.** Operator approval *after* the fact cannot
   authorize the earlier promotion.
   → `reviewed_at` must precede `t_promote`; a receipt minted by/after the transition
   does not count.
   Warrant: `RetroactiveLegitimation.post_validation_does_not_imply_authorization` [annex],
   corroborated by `RetroactiveFigLeaf.post_validation_does_not_imply_authorization` [scratch].
   Composes with our own [[feedback_basis_dependency_over_chronology]]: a receipt may be
   *minted late* but must *testify to a pre-state basis*; basis may not depend on post-state.

3. **Attestation ≠ proposal (actor-relative).** Operator ATTESTS basis-reviewed; the
   builder/producer ASSEMBLES the basis. Operator does not manufacture the basis.
   → `verdict ∈ {basis_reviewed | refused}`, never `eligible`. And: being "authorized"
   does not make the outcome good — the gate still independently evaluates.
   Warrant: `AttestationLedger` (writer posts / auditor attests-revokes; value-blind
   bridge; `authorized_trajectory_loses_value`) [annex].

4. **Freshness — reviewed-within-window, not once-looked.** Stale review can be
   witnessed but is not binding; valid-at-review ≠ valid-at-promote.
   → `reviewed_at` must be fresh at `t_promote` (reuse the existing two-clock
   `standing_spendability` / `clock_witness` discipline AG already ships).
   Warrant: `Freshness.expired_not_fresh` (+ not-yet-valid / incoherent / divergence)
   [annex]; `TemporalCustody.citation_validity_does_not_imply_execution_admissibility`
   [scratch].

5. **No retroactive bridge.** Do not build a path that lets review-time validity
   discharge a later promotion — that collapses the freshness gate.
   Warrant: `RetroactiveBridgePrice.retroactive_bridge_collapses_freshness_gate` +
   `honest_gate_refuses_retroactive_bridge` [scratch].

## Proposed runtime shape (projection — refine at build time)
```
OperatorBasisReceipt:
  operator_id
  basis_bundle_hash            # the exact bundle reviewed (pre-state binding)
  reviewed_at                  # clock witness; must precede t_promote, fresh at promote
  transition_request_hash      # binds to THIS promotion transition
  prior_authority_hash         # pre-state authority (S, not S')
  evidence_bundle_hashes       # the live/replay evidence the basis covers
  replay_holdout_receipt_hash
  refusal_state_snapshot_hash
  verdict: basis_reviewed | refused
```

## Design target: make bad states unrepresentable, not merely refused (Chatty, 2026-06-14)
Imitate the `AmendmentFragment` type-move as far as Python allows. The receipt type
must have **no field** for:
```
promotion_eligible
basis_valid
operator_approved_promotion
```
Those belong to the gate, not the operator receipt — same as `ObservationFacts` has no
`in_bounds`. The receipt's only verdict is `basis_reviewed | refused`. A bad state
("operator says eligible") should be awkward-to-impossible to express, not just caught.

### Two pinned hard constraints (when P4.0g is built)
1. **Pre-state binding is structural, not a late string compare.** The gate takes
   `basis_bundle` AND the `OperatorBasisReceipt` whose `basis_bundle_hash` must match the
   consumed bundle. The receipt **binds** to the basis; it never **carries** basis
   contents as authority. (`consumed_bundle_hash == reviewed_bundle_hash`, enforced at
   the gate, not trusted from the receipt.)
2. **The operator receipt must never become a promotion verdict.** `basis_reviewed` ≠
   `eligible` ≠ `approved` ≠ "James said ship it." It is exactly: *this operator
   reviewed this exact bundle before this transition.*

## Lean specimen — the bool-vs-typed seam, now mechanized (`OperatorBasisGateInput.lean`, [scratch], 2026-06-14)
The current P4.0a gate takes `operator_basis_present: bool`. The specimen proves what
that costs:
- `bare_bool_ignores_bundle (present b₁ b₂) : gateBool present b₁ = gateBool present b₂`
  — by `rfl`. The bool gate's verdict is **provably independent of the consumed bundle**:
  `Bool` has nowhere to put the bundle, so the binding isn't unchecked, it's
  *structurally inexpressible*.
- `bare_bool_gate_collapses_reviewed_bundle_binding` — a detached `true` admits a bundle
  the honest typed binding refuses (reviewed ≠ consumed, typed refuses, bool admits).
- `typed_gate_admits_iff_bound` + `typed_gate_refuses_iff_mismatch` (both directions) —
  no typed `admit` exists without `basis_bundle_hash == hashBundle consumed`; a
  detached-admit is **unrepresentable**, meeting Chatty's "Design target" exactly.

**The honest limit (custody-location caveat, in the specimen header):** this does NOT
prove `bool + mandatory-revalidate-on-consume` unsound. It proves the bool gate input
has **no custody** of the binding — *if another layer restores the binding at consume,
that layer is the real gate and the bool is its redundant shadow.* About where custody
lives, not that the pipeline fails.

**Design call (mine, at P4.0g build time — Lean informs, does not decide):**
the typed input is *strictly stronger* (unrepresentable vs merely caught). The spike
chose bool for wiring-consistency with the other P4.0a inputs — but note the asymmetry:
every other producer input is **checked, not stamped**, and bool-operator-basis is the
one input whose correctness would rest on a *discipline* (re-validate on consume) rather
than the *type*. We outlawed stamp-and-trust everywhere else (`ObservationFacts` has no
`in_bounds`; observations re-derive on load). **Lean recommendation captured: make the
gate take `(basis_bundle, OperatorBasisReceipt)` with structural binding** (Chatty's
pinned constraint #1), so the bad state is unrepresentable here too — UNLESS wiring
genuinely forces bool, in which case the basis layer MUST re-validate binding on consume
and be documented as the real gate. Decide at build, not now.

## The rule (load-bearing)
> OperatorBasisReceipt does NOT establish PromotionEligible. It establishes only that
> the operator reviewed the basis bundle that the promotion gate must independently
> evaluate.

Wires into the existing P4.0a gate input `operator_basis_present: bool` the same way
the other producers do — **checked, not typed**: the basis layer COMPUTES that bool
from a valid OperatorBasisReceipt (pre-state binding holds, reviewed_at < t_promote,
fresh, bundle == consumed bundle), it is never hand-stamped. Producer-derived ≠
producer-trusted carries forward: re-validate on consume.

## Negative theorem-shapes worth pinning as tests (runtime, not Lean)
- `operator_reviewed_basis_does_not_mint_basis` (attest ≠ propose)
- `post_promotion_attestation_does_not_authorize_promotion` (reviewed_at ≥ t_promote → refused)
- `consumed_bundle_must_equal_reviewed_bundle` (bundle hash mismatch → refused)
- `stale_review_not_binding` (review outside freshness window → refused)

## Freshness-window ops scar (runtime config, NOT Lean — flagged by the Lean-side pass)
The staleness gate (keeper #4) and producer latency are **coupled**, and the coupling
is invisible until a slow holdout eats the window:

> **Freshness window must outlive the producer pipeline.** If P4.0f's ReplayHoldout runs
> in the interval `[reviewed_at, t_promote]` and its runtime exceeds the freshness
> window, every promotion fails freshness *on its own pipeline* — the gate that protects
> against stale review DoSes the happy path. Size the window `> max(ReplayHoldout runtime
> + slack)`, OR stop the freshness clock during holdout execution (and say so in the
> receipt).

Scar-shape: the anti-staleness gate and the producer it gates can starve each other.
Decide the window-vs-clock-pause policy when P4.0f/P4.0g are wired; pin a test that a
holdout longer than the window does not auto-fail an otherwise-valid promotion.

## Genesis root / multi-root warrant — now formalized ([scratch], 2026-06-14)
"Qualified operator" is agent_gov's **genesis root** — where No-Negative-Clearance
bottoms out in a human; legitimate and *frame-relative*. This is no longer just a header
warrant; it has a Lean floor (observer-foundation slices, [scratch], axiom-free headline):

- `Force : Consumer → Artifact → Prop`; force-for-A ⇏ force-for-B (`ConsumerRelativeForce`).
- **`no_global_section_when_consumers_disagree`** (axiom-free): a consumer-relative force
  field has **no consumer-independent section** unless consumers agree. This is the
  PCAA/receipt-stamping error as an elementary theorem — the category-theory ghost made
  concrete.
- `universal_root_licenses_stamp` (the positive dual): a universal root is the *only*
  honest absolute stamp; `c_no_universal_root` shows an open consumer world has none.
- `AbsoluteForceStampBridgePrice`: stamping absolute force on the envelope is priced to
  consumer-boundary collapse; the honest gate refuses it.

**Mapping to AG (same theorem, two ends — the spike's seam and this foundation meet):**
- Single-rooted today → `universal_root_licenses_stamp` says AG's absolute operator stamp
  is **legitimate** (the qualified-operator genesis root *is* the universal root).
- Federate AG with a foreign consumer → no shared operator-root →
  `no_global_section_when_consumers_disagree` says the stamp **loses its section**;
  `operator_basis_present` becomes consumer-relative, not absolute. The observer axis
  reopens exactly at the trust boundary.

Consequence for the build: while AG promotion is consumed only under its own operator
root, the receipt's operator stamp is sound. Multi-root is the federation extension
(same discipline as the temporal slices). Still [scratch]-informed, not ratified — a
register/paper promotion would be the operator's call. Not built on the AG side.
